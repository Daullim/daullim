# ADR-005 API 계약 운영 — 스펙 우선(OpenAPI yaml) + 경량 운영

## 상태
승인 (2026-07-20, 결정자: 이윤서)
개정 v1.1 (2026-08-05, 결정자: 이윤서) — 계약 정본 `docs/openapi.yaml` 작성 완료. §2 타입 생성·§3 Prism mock 폐기

## 맥락
- 계약 7종·`visit_result` 페이로드는 확정(PRD v2 §4, ADR-003에서 building_id 개칭). WBS D1 = "API 계약 확정 최우선".
- BE = Spring Boot + Java (ADR-002) — FE와 네이티브 타입 공유 불가, 보완 필요.
- 1주차 FE 병렬 개발이 3주 성패 좌우. 상태 모델 보류(ADR-003 §5) 중에도 FE 진행 필요.

## 검토한 선택지
1. **스펙 우선 + 경량 운영 (채택)**
2. 코드 우선(springdoc 정본) — 계약이 BE 구현 후 생성, 1주차 병렬성 상실로 기각
3. 스펙 우선 + Mock 생략 — Prism 세팅이 사실상 0비용이라 절감 실익 없음

## 결정
1. `docs/openapi.yaml`을 계약 정본으로 작성. 변경은 "계약 변경 PR"로만(양측 확인).
   ~~D1에 작성·동결~~ → **(v1.1)** 실제로는 BE 구현과 같은 PR에서 작성됐다. 1인 개발이라 병렬 대상이 없었고,
   실데이터가 명세 초안과 어긋난 지점(보급이력 전량 NULL·지역 코드 체계 등)이 구현 중에 드러나 동결이 성립하지 않았다.
2. ~~FE 타입: `openapi-typescript` → `types.gen.ts` 생성·커밋~~ → **(v1.1) 폐기.**
   `frontend/src/api/types.ts`에 **손으로 옮긴다.** 타입이 10여 종이라 생성기 도입·유지 비용이 이득을 넘고,
   의존성 0 원칙과도 맞는다. **계약이 바뀌면 이 파일도 같이 고친다**(드리프트 책임은 사람에게 있다).
3. ~~Mock: Prism(`npm run mock`)으로 yaml에서 기동~~ → **(v1.1) 폐기.** 1주차 병렬 개발이라는 전제가
   1인 개발에서 성립하지 않았고, FE는 목데이터(`mock/sample.ts`)로 화면을 먼저 세운 뒤 실데이터로 갈아탔다.
4. BE: 서버 코드젠 없이 수동 구현. springdoc Swagger UI는 구현-스펙 눈 대조용으로만 노출.
5. 드리프트 통제: 통합 체크포인트 수동 대조. CI 자동 검증은 3주 대비 과잉 — 도입 안 함.
   **(v1.1)** 실제 통제는 BE 통합 테스트(도메인별 IT 6종)가 봉투·상태코드·파생값을 잠그는 쪽으로 갔다.

## 근거
- 계약 내용이 PRD v2 §4에 이미 존재 — yaml화는 반나절, 대가로 1주차 FE-BE 완전 병렬.
- "계약 우선 설계로 2인 병렬 개발" 포트폴리오 서사.
- **(v1.1)** 병렬 개발 근거는 실제로 실현되지 않았다(1인 개발). 그럼에도 yaml을 남기는 이유는 달라졌다 —
  **실데이터가 명세 초안과 어긋난 지점을 값 그대로 적어 두는 자리**로서다.

## 결과 (트레이드오프 수용)
- BE 구현-스펙 드리프트 가능성 수용(수동 대조로 통제).
- yaml 유지보수 책임 발생 — 계약 변경 PR 규율로 통제.
- **(v1.1) FE 타입이 손 사본이라 계약과 갈라질 수 있다.** 생성기를 버린 대가이며, 갈라지면 타입이 아니라
  런타임에서 터진다. yaml을 고칠 때 `frontend/src/api/types.ts`를 같은 커밋에서 고치는 규율로 통제한다.
