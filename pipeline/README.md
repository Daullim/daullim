# pipeline — 배치 추론 파이프라인 (M-01 / M-01b)

원본 데이터 → 검증 → 도농 판별 → 점수 → `seed/buildings.csv`·`units.csv`·GeoJSON → DB 적재.
**산출물은 `buildings`·`units` 테이블의 행임.**

## 셋업

```bash
python3.13 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
```

Python 3.13 고정(3.14는 geopandas 휠 미비). 근거는 [ADR-014](../docs/adr/ADR-014-pipeline-dependencies.md).
외부 API 키 2종(`SERVICE_KEY`·`VWORLD_KEY`)은 `pipeline/.env` 또는 `backend/.env`에서 읽는다.

## 테스트

```bash
./.venv/bin/python -m pytest
```

법정동코드(`data/codes/`)가 없으면 관련 테스트는 skip된다 — 원본 배치는 [data/README.md](../data/README.md) 참조.

## 실행 순서

앞 단계의 산출을 뒤가 쓴다. **모든 외부 호출은 캐시를 경유**하므로 재실행 비용은 사실상 0이다.

```bash
./.venv/bin/python -u run_ingest.py        # 1. 원본 적재·검증 (--with-calls 로 신고 5년치)
./.venv/bin/python -u run_region_type.py   # 2. 도농 판별 + v0 성적표   ← 미달이면 여기서 멈춘다
./.venv/bin/python -u run_kernel.py        # 3. λ̂ 진단 (m 추정·동점 소멸·민감도)
./.venv/bin/python -u run_buildings.py     # 4. 건물 마스터 + DDL 검증  ← 최초 1회는 수집에 1~2시간
./.venv/bin/python -u run_vulnerability.py # 5. ②③ 진단 (G1 점검·β 민감도)
./.venv/bin/python -u run_scoring.py       # 6. 점수·순위 + 검증
./.venv/bin/python -u run_seed.py          # 7. seed 3종 동시 산출
./.venv/bin/python -u load_seed.py         # 8. DB 적재 (docker compose up -d 선행)
./.venv/bin/python -u run_ltr.py           # 9. (선택) β 재학습 시도 — 현재 미채택
```

3·5·9는 **진단용**이라 건너뛰어도 산출물이 나온다. 2는 게이트다 — 성적표가 미달이면
도농 판별이 틀린 것이므로 뒤로 진행하지 않는다. `-u`(언버퍼드)를 붙여야 장시간 실행에서
진행 상황이 로그에 실시간으로 남는다.

### 한 번에 — `run_all.py`

손으로 8줄을 순서대로 치면 단계를 빠뜨리기 쉽다. 오케스트레이터가 1~8을 순차 실행하고
**첫 실패에서 멈춘다.**

```bash
./.venv/bin/python -u run_all.py                     # 전 구간
./.venv/bin/python -u run_all.py --skip-diagnostics  # 3·5 생략
./.venv/bin/python -u run_all.py --from 6            # 6단계부터 (앞 산출물 재사용)
```

각 `run_*.py`의 `main()`을 **그대로 호출**하는 얇은 래퍼다 — 단계 하나만 다시 돌리고 싶으면
예전처럼 그 스크립트를 직접 실행해도 결과가 같다. 9단계(`run_ltr`)는 미채택이라 넣지 않았다.

통합 로그는 `pipeline/logs/run-all-{타임스탬프}.log`에 콘솔과 **동시에** 남는다(gitignore 대상).

| 종료코드 | 뜻 |
|---|---|
| `0` | 전 단계 통과 |
| `1` | 어느 단계가 미달 — 게이트(2 성적표 · 4 DDL 검증 · 7 seed 검증)가 여기로 온다 |
| `2` | 함정 감지(`DataTrapError`)나 예상 못 한 예외 |

## 규칙 셋 (어기면 조용히 틀린 답이 나온다)

- **인코딩을 추측하지 않는다.** `read_csv_kr()`이 UTF-8-SIG → cp949 순으로만 시도한다. `chardet` 금지.
- **비교·조인 전에 NFC.** 원본 파일명이 NFD와 NFC로 섞여 있어 표준 `glob`이 조용히 0건을 낸다 → `glob_kr()`.
- **범위 검사와 충전율 리포트는 한 쌍이다.** 습도·적설 스왑은 범위 검사를 **통과한다**. 충전율 비대칭이 실제 탐지 수단.
- **격자는 코드 대 코드로 붙이지 않는다.** 좌표 → `cell_key()`(EPSG:5179, 500m 스냅)가 정본 경로.
  `grid500_to_1km()`은 문자열 유도 경로이며, 두 경로를 **자체 대조**해서 쓴다.
- **시군구 코드는 체계를 명시해서만 꺼낸다.** `sigungu_code("imsil", "mois")` — 인자 없이 못 꺼내게 막아 뒀다.
- **코드 검증은 "존재"가 아니라 "현행"으로 한다.** 폐지 코드가 실존해서 통과해 버리는 케이스가 있다(부산 `21` = 폐지된 부산직할시).
- **원인이 다른 손실을 한 숫자로 합치지 않는다.** '격자 미부여'(→읍면동 상향 집계)와 '시도 경계 밖'(→클리핑)은
  후속 처리가 다르다. 합치면 클리핑이 실제로 한 일을 알 수 없다. 연도별 건수도 마찬가지로
  **분류 정책 드리프트와 격자 커버리지 드리프트를 나란히** 낸다 — 아래 실측이 그 이유다.

## 검증된 실측 (재현 가능)

- `grid500_to_1km` — 서울 2023 화재 **5,646/5,646 = 100.00%**가 SGIS 경계 격자에 적중.
  ⚠️ 대조 상대는 경계 SHP(8,609셀)여야 한다. 인구통계(7,008셀)로 대조하면 9셀이 빠지는데,
  그건 유도 실패가 아니라 **무인구 격자 = NO_POP 신호**다(§2-2의 '비정형 주거 확인 큐' 후보).
- **두 경로 자체 대조(§4-5)** — 좌표 변환 경로와 문자열 유도 경로가 **5,645/5,646 = 99.98%** 같은 셀을 가리킨다.
  불일치 1건은 500m 경계에 정확히 걸친 점의 반올림 차이(`다사45b41b` vs `다사45a41b`)다.
  존 원점은 `가나다라마바사` 인덱스로 유도된다(`zone_origin()`): x = 700000 + i·100000 / y = 1300000 + j·100000.
  실측 6개 존(다사·마라·마마·다마·라마·나마) 전부를 테스트가 잠근다.
- 좌표↔코드 대조를 3개 시도로 확대 — 서울 99.98% · 부산 100.00% · 전북 100.00%.
- `DSPT_REQ_HR`은 **초 단위**다. 서울 평균 355초 ≈ 5.9분으로 정의서 URBAN 실측과 일치 —
  도농 완충대 임계값 420s와 같은 축임이 확인됐다.
- 지역 코드 3종 대조표와 검수 7항목은 [data/README.md](../data/README.md)에 있다.

### v0 성적표 (§7) — 3개 시도 합산, `run_region_type.py`

| 지표 | 실측 | 목표 | |
|---|---|---|---|
| 플랫폼 라벨 일치 URBAN | **879/925 = 95.0%** | 95% | 통과 |
| 플랫폼 라벨 일치 RURAL | **985/1,236 = 79.7%** | 80% | 통과(정의서 값의 반올림 전 수치) |
| 출동소요 단조성 | 6.7 → 7.7 → 12.6 → 13.6분 | 단조 증가 | 통과 |

정의서 인용값(879/925·985/1236·NO_POP 54셀)과 **표본 크기까지 일치**한다. 대조 규약이 핵심이라 못 박아 둔다:

- 유니버스 = **3개 시도 합산**(시도별로 쪼개면 안 된다 — 서울은 읍·면이 없어 RURAL 표본이 성립하지 않는다)
- **저장값 `region_type_cd`가 URBAN/RURAL인 격자만** — BUFFER·NO_POP 제외
- 분모는 **판별 기준**(행 방향). 플랫폼 기준으로 재면 URBAN 75.5%·RURAL 91.3%로 전혀 다른 수가 나온다

**플랫폼 라벨 `CTY_FRMVL_SE_NM`은 밀도가 아니라 행정 구분이다** — 교차표가 100% 결정적이다(동→도시, 읍·면→농촌).
우리 판별은 DEGURBA 밀도 기준이므로 두 지표는 서로 다른 것을 잰다. 불일치 격자를 열어 보면
실제로 인구 116~129명/km²의 저밀도 지역(정분류 도시 격자는 5,245~11,064)이라 **판별이 틀린 게 아니라 축이 다르다.**
100% 일치는 목표가 아니며, 목표를 넘겼다고 해서 두 라벨이 같은 개념이 되는 것도 아니다.

### 커널 강도 λ̂ (`run_kernel.py`)

**격자 내 동점이 실제로 사라진다** — 상위 20개 격자를 100m 간격으로 채운 2,000개 점이
전부 서로 다른 λ̂를 받는다(고유값 2,000/2,000 = 100%). 격자 내 최대/최소 비율 중앙값은
서울 3.8배 · 부산 2.8배 · 전북 5.4배다. 격자 전용 모델이면 이 값이 정의상 1.0배(완전 동점)이고,
동점 블록 안에서는 조건부 AUC가 0.5로 고정된다.

**분자는 주거 화재만 쓴다(2026-08-04 재론 확정).** 근거와 그 효과는 아래 § 재론에 있다.

**EB 축소 m — 클래스별 모멘트 추정(주거 화재 건수, w_sev 없는 순수 사건 수 기준)**

`run_kernel.py`는 **시도 단위 진단값**을 낸다:

| 시도 | URBAN | RURAL |
|---|---|---|
| 서울 | m=3,348.8 · λ̄=0.000219 | m=166.0 · λ̄=0.000017 ← Var≤0, P90 상한 |
| 부산 | m=3,977.6 · λ̄=0.000230 | m=93.0 · λ̄=0.000094 ← Var≤0, P90 상한 |
| 전북 | m=1,826.8 · λ̄=0.000153 | m=70.0 · λ̄=0.000494 ← m>P90 상한 |

⚠️ **실제 점수에 쓰이는 값은 이 표가 아니다.** `run_scoring.py`가 시연 유니버스
(관악+임실 합산)에서 다시 추정하며, 그 값은 `seed/score_params.json`에 남는다
(`m_urban=3,142.9` · `m_rural=94.0`). 위 표는 시도별 거동을 보기 위한 진단이다.

RURAL 세 곳이 모두 상한 클립인데 **원인이 다르다** — 서울·부산은 `Var≤0`(주거 화재가 성겨
관측 산포가 Poisson 노이즈를 넘지 못함 = 진짜 이질성 없음), 전북은 `m>P90`이다.
두 경우를 한 코드로 뭉치면 진단이 불가능해서 리포트가 사유를 나눠 찍는다.

**m 민감도는 튜닝이 아니라 보고다.** 사망 라벨이 시도당 7~16셀 소표본이라 포집률로 m을 고르면
노이즈에 과적합한다. 라벨 없이 상위 10% 집합의 자카드 유사도만 본다 —
m×0.5에서 0.887~0.923, m×2.0에서 0.778~0.942로 순위가 안정적이다.

### 재론 — λ̂ 분자를 주거 화재로 한정

| | 주거 비중(건수) | 주거 비중(사망) | w_sev 증폭 |
|---|---|---|---|
| 서울 | 39.7% | **79.2%** | 1.08배 |
| 부산 | 32.4% | **72.7%** | 1.03배 |
| 전북 | 21.8% | **60.0%** | 1.11배 |

`w_sev`가 이 비대칭을 **거의 보정하지 못한다** — 사망·부상 사건이 드물어(서울 5,646건 중 303건)
대부분의 화재가 `w=1`로 균등 취급된다. 즉 분자는 사실상 화재 '건수' 강도이고,
그래서 **무엇을 넣느냐가 어떻게 가중하느냐보다 중요하다.**

효과는 부산에서 결정적이었다. 주거 사망 포집률 @상위 10% 격자:

| | 전체 화재 | **주거만** | (참고) 가구수 기준 |
|---|---|---|---|
| 서울 | 94.7% | 94.7% | 94.7% |
| 부산 | **0.0%** | **100.0%** | 100.0% |
| 전북 | 77.8% | **88.9%** | 22.2% |

전체 화재를 쓰던 때 부산 λ̂ 상위 10%를 **가구 2.1개짜리 초소형 노출 격자**가 점령했다
(전체 중앙값 14.5). 시골 도로의 차량 화재가 빈 셀에 꽂혀 스파이크를 만든 것이다.
주거 한정만으로 이 병이 사라졌다 — **별도의 스파이크 완화 장치는 넣지 않았다.**
완화 3안(하한 상향·노출 플로어·가구가중 하한)을 실측 비교했으나, 하나는 무효 조치이고
나머지는 사망 1명 차이에 상위 10%의 79%를 갈아치우는 수준이라 전부 기각했다.

구현에서 조심한 두 가지:
- **가구를 격자 중심 한 점에 몰지 않는다.** 셀 모서리는 중심에서 636m라 K=0.039까지 떨어져
  E_i가 급락하고 λ̂가 인위적으로 치솟는다. `spread_exposure()`가 셀 안에 5×5로 펼친다.
- **버킷팅은 근사가 아니다.** 컷오프 3σ=750m가 3×3 이웃(±1000m)에 완전히 들어가므로
  전수 비교와 결과가 같다 — 테스트가 이를 대조한다.

### 건물 마스터 (`run_buildings.py`)

원본은 **건축HUB OpenAPI**다(세움터 `open.eais.go.kr`은 폐지). 표제부 → 유형 판정 →
지오코딩 → `buildings`/`units` 조립까지가 한 흐름이고, 모든 호출은 캐시를 경유한다.

**주택 유형은 대장에서 5분류로 오지 않는다.** 표제부는 건축법 상위 범주('단독주택'/'공동주택')로만
주고, 세부 유형이 명시된 건 실측 2,258건 중 11.3%뿐이다. 그래서 명시값 우선 + 건축법 추론 폴백을 쓴다:

```
etcPurps 명시 → 그대로 (아파트/연립/다세대/다가구/다중)
단독 계열 → fmlyCnt ≥ 2 ? multi-family : detached
공동 계열 → 5층 이상 ? 아파트(제외) : (연면적 > 660㎡ ? row-house : multi-unit)
```

660㎡·5층은 건축법 시행령의 실제 구분 기준이다. 교차검증 — 명시적 '연립주택'(3층·2,179㎡·19세대)이
추론 규칙으로도 `row-house`로 떨어진다. **아파트는 스코프 밖이라 제외**한다(DDL 5분류에도 없다).

**세대수는 유형별로 다른 필드에 담긴다**(ADR-015가 실데이터 확인 후 확정하기로 남겨둔 항목):

| 계열 | 필드 | 충전율 |
|---|---|---|
| 단독·다중·다가구 | `fmlyCnt`(가구수) | 94~100% |
| 공동주택·다세대·연립 | `hhldCnt`(세대수) | 100% |
| `hoCnt` | 거의 안 씀 | 1.6~20% |

단, **단독·다중의 `unit_count`는 무조건 1이다.** ADR-015가 "1행, `ho_nm='본가구'`"로 규정했으므로
그래야 `units` 행수와 정합한다. 실측에 `fmlyCnt=0`인데 `hoCnt=16`인 단독주택이 있었고,
`hoCnt` 보조 규칙을 그대로 두면 "행 1개인데 `unit_count` 16"이 되어 검증이 깨졌다.

**지오코딩은 VWorld 도로명 검색이 정본이다.** 응답의 `level4AC`가 행정동코드를 함께 주므로
`admin_dong_cd`를 추가 호출 없이 채운다. 도로명이 없거나 실패하면 지번(`parcel`)으로 폴백하는데,
**지번 검색은 `level4AC`를 주지 않는다**(실측). 폴백한 행은 `is_estimated=true`로 표기한다 —
유형 추론은 이 플래그에 싣지 않는다(지오코딩 정확도와 의미가 섞이면 화면 배지가 흐려진다).

**실측 결과 (2026-08-05, `run_buildings.py`)** — buildings **30,593행** · units **94,074행**, DDL 전량 통과.

| | 관악구 | 임실군 |

| 표제부 | 31,765 | 16,973 |

| buildings | 22,501 | 8,092 |

통째로 죽은 실측이 있다. `OSError`·`HTTPException`까지 잡는다.

### ②③ 취약·상대위험 (`run_vulnerability.py`)

**G1 이중 계상 — 겹침 0건.** $V^\perp$는 `pct(고령율) × pct(1인가구율)`이고,
**비아파트율·노후율은 은퇴**시켰다 — 각각 ③의 x₃(주용도 prior)와 x₁(연차)이 이미 본다.
코드가 이 대조를 자동 출력한다. 백분위는 **URBAN 클래스 내부에서만** 계산한다(§2-2 P2 교훈).

실측: URBAN 격자 2,771 · $V^\perp$ 중앙 0.211 · 지역 배수 중앙 **1.21배** · 최대 1.99배.

**β 확정값 — `β_age=0.5` · `β_struct=0`.** x₃(ln1.36/ln0.73)만 NFDS 실측이고 나머지는 판단값이다.
LTR로 재학습을 시도했으나 **미채택**했다(아래 § LTR) — 회신 데이터가 쌓이기 전까지 이 값을 쓴다.

- **x₂를 끄는 근거는 G1 잔차화의 연장이다.** 취약 구조 해당 비율이 관악 **1.7%** 대 임실 **47.5%**로
  갈린다(블록구조·슬레이트가 농촌에 몰림). 켜면 사실상 '농촌 전체 가산'인데 도농은 이미 분기 처리된다.
- **x₁을 켜는 근거는 동점 파괴가 아니다.** 아래 실측이 브리프 예상과 다르다.

| | 최종 점수 고유값 | 최대 동점 블록 |
|---|---|---|
| x₃만 | **93.64%** | 52 |
| + x₁(β=0.5) | 95.22% (+1.6%p) | 52 |
| + x₁ + x₂ | 95.58% (+0.4%p) | 52 |

§2-1은 x₁을 "동점 파괴 주력"이라 했지만, **λ̂가 이미 93.6%를 만든다.** x₁의 기여는 1.6%p이고
최대 동점 블록 52는 셋 다 동일하다(연차 결측 건물들이라 x₁=0으로 묶인다).
x₁을 켜는 실제 근거는 **노후 건물에 가중을 준다**는 도메인 판단이며, 실측 추정치가 아니다 —
화재-건물 매칭이 필요한데 관악구 주거화재 표본이 수십 건이라 추정이 성립하지 않는다.

**사용승인일에 997년·1046년이 있다.** DDL `CHECK`가 형식(`^\d{8}$`)만 보고 연도 범위를 안 봐서
그대로 통과했고, x₁ 연차가 1029년이 되어 `rr`이 **1e15**까지 폭발했다. 두 겹으로 막았다 —
1900년 미만은 결측 처리(`install_year` CHECK가 1990~2100인 것과 같은 발상), 그래도 남는
1916년생 한옥 같은 실값을 위해 **연차 100년 상한**. 지수형은 꼬리 하나가 배수를 지배하므로
입력 정제만으로는 부족하다.

### 점수·순위 (`run_scoring.py`)

```
score — 중앙 53.7 · p90 81.7 · 최소 0.0 · 최대 100.0
risk_level — warn 14,567(47.6%) · ok 8,403(27.5%) · danger 7,622(24.9%)
order_key 1..30,593 유일·연속 · 탐사 쿼터 7.0%
블록 — 농촌대상 5,403 → 도시 23,409 → 농촌기타 1,781
```

**블록 배치 — 정렬 논리가 다른 집단은 섞지 않는다.** 농촌은 랭킹을 포기하고 필터로 대상을
확정한 뒤 가구 속성으로 정렬하므로(§2-2), 도시의 score 정렬과 한 목록에 섞을 수 없다.

| 블록 | 대상 | 정렬 |
|---|---|---|
| 0 | 농촌 절대필터 통과 | 사용승인일 ASC → 1인가구율 DESC → 소방서거리 DESC |
| 1 | 도시 | score DESC → 연차 DESC → 동선(Z-order) ASC |
| 2 | 농촌 필터 미통과 | 블록 1과 같은 캐스케이드 |

화면은 항상 시군구로 필터되므로(`sido_cd`·`sigungu_cd`·`admin_dong_cd`) 전역 계층 정렬이
곧 시군구 내부 블록 순서가 된다. 실측 — 관악구는 URBAN만이라 블록 1 단일(score 순),
임실군은 블록 0(5,403) → 1(894) → 2(1,781)로 쌓인다.

**보급이력 전량 NULL로 두 정렬축이 무력화돼 대리를 쓴다** — 도시 2단 '만료확률 DESC' →
**연차 DESC**, 농촌 1순위 '보급연차 DESC' → **사용승인일 ASC**. 보급이력이 들어오면 복귀한다.

**`score_version`은 varchar(20)이라 파라미터를 못 담는다.** §2-5는 변환 파라미터를
버전에 박으라고 하지만 20자에 안 들어간다 — 버전은 **키**로만 쓰고 값은
`seed/score_params.json`에 남긴다(q01·q99·α·m·λ̄·β). 재현 목적은 그대로 달성된다.

**정렬에서 잡은 버그 2건.**
- **결측 사용승인일이 큐 1등을 차지했다.** `_age_days`의 결측을 0으로 두면 실제 날짜
  (-738,000 근처)보다 커서 DESC 정렬에서 맨 앞으로 온다 — '모름'이 '가장 오래됨'으로 둔갑했다.
  실측에서 임실군 큐 상위 5건이 전부 결측이었다. `-inf`로 맨 뒤로 보낸다.
- **NO_POP 격자의 건물 1건이 통째로 빠졌다.** NO_POP은 '인구 0'이지 '건물 0'이 아니고,
  실제로 집이 서 있으면 점검 대상이다. 격자 매핑 실패분과 함께 URBAN 기본값으로 넣는다.

### ⚠️ 사본 동기화 — 재산출 시 반드시 함께 갱신

`seed/`가 정본이지만 같은 파일이 다른 곳에도 있다. **한 곳만 고치면 화면과 서버가 다른 데이터를 본다.**

| 파일 | 사본 위치 | 왜 사본이 필요한가 |
|---|---|---|
| `regions.csv` | `backend/src/main/resources/` | `Dockerfile` 빌드 컨텍스트가 `backend/`뿐이라 컨테이너 빌드에서 `../seed`가 안 보인다 |
| `grids.geojson` | `backend/src/main/resources/` | 위와 같음 |
| `admin-dong-boundaries.geojson` | `backend/src/main/resources/`<br>`frontend/public/` | 위와 같음 + **FE 폴백** — `GET /regions/boundaries`가 실패하면 화면이 `/admin-dong-boundaries.geojson`을 직접 읽는다(인증 오류 401·403은 폴백하지 않는다). 이 사본은 `dist/`에도 그대로 실려 번들이 225KB 커진다 — 폴백을 접으면 `frontend/public/` 사본과 `queries.ts`의 폴백 분기를 함께 지운다 |

세 산출물은 **한 실행에서 임시 파일에 쓴 뒤 일괄 rename**한다(ADR-008 §9) — 중간에 실패하면
'버전이 어긋난 CSV와 GeoJSON'이 남는 게 가장 위험하다.

**적재에 파이썬 DB 드라이버를 쓰지 않는다.** 컨테이너의 `psql`을 `docker exec`로 호출해
`\copy`한다 — ADR-014의 의존성 최소화를 지키면서 ADR-012 결정 12의 COPY 방식을 그대로 만족한다.

**멱등성·경계 실측 검증.** 업무 상태를 일부러 바꿔 두고 재적재했다:

| | 1회차 | 재적재 |
|---|---|---|
| `buildings` | INSERT 30,593 | UPSERT (행수 유지) |
| `units` | INSERT 94,074 | **INSERT 0** (DO NOTHING) |
| 바꿔둔 `status_cd='done'` 3건 | — | **보존** |
| 바꿔둔 `last_inspected_day` 3건 | — | **보존** |

ADR-015의 쓰기 경계가 실제로 작동한다 — 월 1회 재실행이 현장 회신을 덮지 않는다.

**BE 기동 확인.** `./gradlew bootRun`이 4.8초에 정상 기동한다. `ddl-auto=validate`가 통과했다는
것은 우리 산출이 스키마와 정합한다는 뜻이다. 세대 행이 없는 건물은 **0건**이라
`visits.unit_id`(NOT NULL) 제약도 만족한다 — 점검 폼 진입의 전제 조건이다.

**✅ 화면 확인 완료 (2026-08-05).** §7의 최종 통합 확인 "화면에서 목데이터 아닌 실데이터가 큐로 뜨는가"가
조회 API 10종과 FE 연동으로 달성됐다. 아래는 SQL로 재현해 뒀던 큐 1등인데, 화면에서도 같은 행이 1등으로 뜬다:

     5407 | 서울특별시 관악구 광신1길 15     | 100.00 | danger | RX-IOT | 미보급 · 동선 5407

파이프라인 산출과 화면이 같은 수를 말하는지 교차 대조한 값들:

국토부 500m 경계를 확보하면 유도를 걷어내고 저장값을 바로 쓴다.

### ADR-010 시연 지역 교체 조건 — **교체 불필요** (2026-08-05 실측)

건물 단위 데이터가 생겨야 판단할 수 있던 항목이다(격자는 100km 존 단위라 시군구와 무관).

| 조건 | 실측 | 판단 |
|---|---|---|

### ⚠️ SGIS long 포맷의 0값 생략 — 조용히 농촌을 지우던 버그

②를 판단하다 발견했다. 처음엔 **필터 충족이 0건**으로 나왔는데, 원인은 데이터가 아니라 적재 코드였다.

**SGIS long 포맷은 값이 0인 항목을 행으로 내보내지 않는다.** pivot 후의 결측은 '모름'이 아니라
**0채**인데, 이를 NaN으로 두면 아파트가 한 채도 없는 격자에서 비아파트율이 계산되지 않는다.
남은 격자만 보니 전북 아파트율 중앙값이 **0.728**이라는 불가능한 수가 나왔다(비아파트율 결측 94.6%).
다마존 대조가 결정적이었다 — 총주택 6,912격자 중 아파트 행은 **372개뿐**이고 나머지는 아파트 0채다.

**하필 우리가 찾는 농촌 취약 지역이 통째로 빠지는 방향의 버그였다.** 0으로 채우자
임실군 비아파트율 중앙값이 0.67 → **1.000**이 되고 필터 충족이 0 → **5,518건**으로 뒤집혔다.

도농 판별 v0 성적표는 **영향이 없었다**(879/925·985/1236·단조성 모두 동일) — 완충대
타이브레이크의 `아파트율 ≥ 0.5`가 NaN이든 0이든 똑같이 False였기 때문이다. 우연히 방향이 맞았을 뿐이다.

### β 재학습 (LTR) — **미채택, v0 유지** (`run_ltr.py`)

브리프 §7의 "사망 라벨 pairwise LTR"은 **시연 지역 규모에서 성립하지 않는다.**

| 라벨 | 양성 | 격자 |
|---|---|---|
| 사망 | **2건** (관악 2 · 임실 0) | 2 |
| 주거화재 발생 | 148건 | 35 |

사망 양성 2건으로 3개 파라미터를 추정할 수 없다. 대체 라벨(주거화재 발생)로 돌려 봤더니
`x1_age`가 **−0.738** [CI −1.108, −0.392]로 유의하게 **음수**였다 — v0의 +0.5와 부호가 반대,
즉 "신축일수록 위험"이다.

**교란이었다.** 화재는 세대 단위로 나는데 라벨은 건물 단위라, 세대가 많은 건물이 라벨을
받을 확률이 높다:

| | 세대수 중앙 | 세대수 평균 |
|---|---|---|
| 화재 발생 건물 | **5.0** | 5.11 |
| 미발생 건물 | **1.0** | 3.07 |

연차 구간별 평균 세대수를 보면 45년+ 구간이 1.15로 급락한다 — 아주 오래된 건물은 단독주택
1세대다. 그래서 "연차↑ → 세대↓ → 라벨 확률↓"이 되어 β가 뒤집혔다. 포집률이
14.9%→27.0%로 오른 것도 같은 교란을 학습한 결과다(세대 많은 건물을 상위로 올림).

**채택하면 §1-2의 기준에 정면으로 걸린다** — "데이터가 침묵하는 가구를 명단 위로 올리는가,
아니면 이미 잘 보이는 가구를 다시 세는가". 세대 많은 신축은 이미 잘 보이는 쪽이다.
§2-1이 `w_sev`를 둔 이유도 같다 — 빈도 모델은 PoC에서 이미 실패했다(화재 33~39% vs 사망 10~25%).

→ **v0 β(0.5, 0)를 유지**한다. 채택 규칙을 코드에 넣었다: **CI가 0을 포함하거나
노출량 교란(양성/음성 세대수 배율 ≥ 2)이면 학습값을 쓰지 않는다.**

**시간 분할 백테스팅은 미착수로 남긴다.** 119신고 다년 이력(2019~2022)을 건물 단위로
귀속시켜야 하는데 신고 좌표 충전율이 58~78%라, 귀속 실패분이 라벨을 왜곡한다.
위 포집률은 전부 **인샘플**이며(λ̂를 만든 화재가 라벨에 포함) 절대 성능으로 인용할 수 없다.

### PoC 인용값과 어긋난 것 (지어내지 않고 그대로 적는다)

- **"미클리핑 시 14배 팽창"은 재현되지 않았다.** 우리 실측은 서울 500m 기준 **1.9배**(2023: 15,623→8,395),
  1km 기준 **3.7배**(5년 누적: 18,987→5,192)다. 클리핑이 필요하다는 결론은 그대로지만 배율은 다르다.
  PoC의 34,037/2,420이 어떤 집계 단위였는지 확인되지 않아 **미재현으로 남긴다.**
- **2021 급증은 시도마다 성격이 다르다.** 부산의 격자 기준 2.65배 증가(229,588→609,102)는
  신고가 늘어서가 아니라 **격자 부여율이 27.4%→65.5%로 뛴 커버리지 변화**다(원본 행수는 838k→938k로 완만).
  반면 **화재 분류 건수의 증가는 실재**한다 — 서울 20,348→31,628(1.55배), 전북 7,872→12,830(1.63배).
  두 드리프트가 겹쳐 있으므로 리포트가 원본 행수와 격자부여율을 나란히 낸다.
- **'활동 있는 침묵' 격자** — 서울 293 · 부산 78 · 전북 322 (5년 누적, 총신고 50+ / 화재신고 0).
  PoC 인용값(265 · 135 · 481)과 같은 규모대이나 **정확히 일치하지는 않는다**(집계 기간·클리핑 기준 차이 추정).
- 화재 상품에는 **시도 경계 밖 행이 0건**이다. 클리핑 함정은 신고 상품에만 있다.
- **NO_POP 승격 대상이 0건이다.** 54셀·화재 59건·사망 2명은 PoC 인용값과 정확히 재현되지만,
  그 59건의 구성은 자동차/철도차량 21 · 기타 19 · 임야 5 · 교육 4 · 산업 4 · 기타서비스 4 · 집합 2로
  **주거화재가 0건**이다. 사망 2명도 차량 화재다(군산 옥서면·진안 상전면).
  §2-2 규칙(`P=0 ∧ 주거화재>0`이면 승격)을 그대로 적용하면 전량 모델 제외가 맞다 —
  구현은 규칙대로 동작한다. 다만 **"통계 부재가 곧 최고 취약의 신호"의 근거로 이 사망 2명을 인용하면 안 된다**(2023 단년 기준).
- **신고 유형별 격자 부여율이 다르다** — 전북 2023 기준 화재 63.2% vs 구급 88.9%(서울은 85.1% vs 93.8%).
  '활동 있는 침묵' 지표가 이 편차에 교란될 수 있다. 화재 신고가 유독 격자를 못 받는 만큼
  '화재 0'이 과대 계상된다는 뜻이라, 해당 격자 수는 **상한으로 읽어야 한다.**
